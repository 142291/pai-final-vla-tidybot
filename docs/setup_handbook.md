## 1. キット開梱チェック

構成: **リーダー 1 本 + フォロワー 1 本**(基板 2 枚、モーター 12 個)。

- モーター 12 個(Feetech STS3215)。**フォロワー用 6 個は全部 1/345 ギア**。**リーダー用 6 個は軸ごとに違う**。
  見分け方はモーター側面のシールにある **型番コード**(`ST3215-C0xx`)。ギア比そのものは書いていないことが多い。

  | コード | 電圧 | ギア比 | 使う場所 | 個数 |
  | --- | --- | --- | --- | --- |
  | `C001` | 7.4V | 1/345 | フォロワー全 6 軸 + リーダー 2 肩上下 | 7 |
  | `C044` | 7.4V | 1/191 | リーダー 1 肩回転、3 肘 | 2 |
  | `C046` | 7.4V | 1/147 | リーダー 4 手首上下、5 手首回転、6 グリッパ | 3 |
  | `C018` など | 12V | 1/345 | 12V 版キットのフォロワー(リーダーには使わない) | (6) |

  「1/345」は内部ギアの減速比。数字が大きいほどトルクが強く、手で回すと重い。リーダーは人が軽く動かせるよう減速比の小さい
  C044/C046 を使い、自重を支える肩上下だけ C001 にしている。混ぜるとリーダーが重くて操作できない/フォロワーが力不足になる。
  電源を入れていない状態で出力軸を指で回すと、C046 < C044 < C001 の順に重くなるので、シールが読めないときの補助になる。
- モーターバス基板 2 枚(USB-シリアル)。Waveshare 基板ならジャンパ 2 本を **B(USB)側**にする。
  どちらがリーダー用かはテープで印を付けておくと後で迷わない。
- 電源アダプタ。電圧はモーターの版(7.4V / 12V)に合わせる。
- 3 ピンケーブル、M2×6 / M3×6 ネジ、モーターホーン。

キットが「組み立て済み」なら §3 の組み立ては飛ばせるが、**モーター ID(§2-2)が設定済みかは要確認**。
未設定だと全モーターが ID=1 で衝突して動かない。組み立て済みかどうかで `scripts/00_check_usb.sh` → §2-1 から入るのは同じ。

## 2. モーター設定(基板 1 枚ずつ、組み立て前に)

### 2-a. 基板への電源配線(先に必ず読む)

基板(Waveshare Bus Servo Adapter (A) 系)は **USB からモーター電源を取らない**。USB と外部電源の両方が必要。

| 電源の形 | つなぎ先 |
| --- | --- |
| DC プラグ(5.5×2.1mm) | 基板の DC ジャック |
| 赤・黒のむき出し線 | 緑のネジ端子。**赤 → `VIN`(または `+`)、黒 → `GND`(または `−`)** |

- 端子の横のシルク印字(VIN/GND や +/−)を必ず見てから締める。逆接すると基板やモーターが壊れる。
- 芯線のヒゲが隣の端子に触れないよう、しっかり撚ってからネジを締める。
- **電圧はモーターの版に合わせる**。モーター側面のラベルで確認:
  - `ST3215 C001` / `C044` / `C046` → 7.4V 版(5V〜8.4V 給電。キット付属は 5V 4A が多い)
  - `ST3215 C018` / `C047` → 12V 版(9V〜12.6V 給電。12V 2A など)
  - **リーダーは常に 7.4V 版**。キットに 5V と 12V の 2 種類のアダプタが入っていたら、12V はフォロワー専用。リーダーに 12V を入れると焼ける。
- ジャンパ 2 本は **B(USB)側**。A は ESP32/Raspberry Pi の UART 用。
- 基板 2 枚は同時に USB につないでよい(それぞれ別の `/dev/tty.usbmodem…` になる)。電源もそれぞれに必要。

### 2-0. まず USB 認識だけ確認

```bash
scripts/00_check_usb.sh
```

`/dev/tty.usbmodem…` が 2 つ見えれば OK。0 個なら USB ケーブル(充電専用ケーブルは不可)を疑う(USB シリアル自体は外部電源なしでも見える)。
2026-09-05 に 1 枚目として認識されたのは `/dev/tty.usbmodemXXXXXXXX`。ポート名は基板ごとに固定なので、どちらのアームに使ったかを記録しておく。


もう一度実行し、今度は **フォロワー側だけ**抜いて Enter → `FOLLOWER_PORT`。


### 2-2. モーター ID とボーレートの書き込み(1 回だけ)

```bash

scripts/02_setup_motors.sh leader
```

`scripts/02_setup_motors.sh both` でフォロワー → リーダーの順に連続実行もできる。

**基板にモーターを 1 個だけ**つないで Enter。他のモーターとデイジーチェーンしない。
エラーが出たら「電源」「USB」「3 ピンケーブル」の 3 つを確認する。

## 3. 組み立て

公式手順(関節ごとの動画つき): https://huggingface.co/docs/lerobot/so101#step-by-step-assembly-instructions
モーターのシール: **R-n = フォロワー、L-n = リーダー**(n = モーター ID = 関節番号)。

共通ルール:

- 各モーターは置いた直後に 3 ピンケーブルを 1 本挿しておく(後から挿しにくい)。
- ホーン(出力軸の円盤)は上下 2 個。**上ホーンだけ M3×6 のホーンネジで固定、下ホーンはネジ不要**。
- モーター本体の固定は **M2×6(いちばん小さいネジ)×4**、パーツ同士の固定は **M3×6**。
- 3D プリント品はサポート材の残りを小さいドライバーで取り除いてから使う。
- 配線は基板 → 1 → 2 → 3 → 4 → 5 → 6 の順に数珠つなぎ。

### フォロワー(R-1〜R-6)・リーダー(L-1〜L-5)共通: 関節 1〜5

| 順 | 使うモーター | 手順 |
| --- | --- | --- |
| 関節 1 | R-1 / L-1 | ①ホーン上下を付け上ホーンを M3×6 で固定 → ②モーターをベースに入れる → ③M2×6 ×4 で固定(上 2 本・下 2 本) → ④モーターホルダー 1 をかぶせて左右 M2×6 ×1 ずつ → ⑤肩パーツを載せ、上 M3×6 ×4・下 M3×6 ×4 → ⑥肩モーターホルダーを付ける |
| 関節 2 | R-2 / L-2 | ①ホーン上下、上を M3×6 → ②モーターを上から差し込む → ③M2×6 ×4 → ④上腕を左右 M3×6 ×4 ずつで固定 |
| 関節 3 | R-3 / L-3 | ①ホーン上下、上を M3×6 → ②モーターを入れて M2×6 ×4 → ③前腕を左右 M3×6 ×4 ずつで固定 |
| 関節 4 | R-4 / L-4 | ①ホーン上下、上を M3×6 → ②モーターホルダー 4 をかぶせる → ③モーターを差し込む → ④M2×6 ×4 |
| 関節 5 | R-5 / L-5 | ①モーターを手首ホルダーに入れ、前面 M2×6 ×2 → ②ホーンは **上 1 個だけ**、M3×6 で固定 → ③手首を関節 4 のホーンに左右 M3×6 ×4 ずつで固定 |

動画: Joint1 https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobot/Joint1_v2.mp4 、
以下 `Joint2_v2.mp4` `Joint3_v2.mp4` `Joint4_v2.mp4` `Joint5_v2.mp4` `Gripper_v2.mp4` `Leader_v2.mp4` を同じ URL の末尾で置き換え。

### フォロワーの先端: グリッパ(R-6)

1. グリッパ本体を関節 5 のホーンに M3×6 ×4 で固定。
2. R-6 を入れて左右 M2×6 ×2 ずつで固定。
3. R-6 にホーン上下を付け、上ホーンを M3×6 で固定。
4. 可動爪を左右 M3×6 ×4 ずつで固定。

### リーダーの先端: ハンドル+トリガー(L-6)

1. リーダーホルダーを手首に M3×6 ×4 で固定。
2. ハンドルをリーダーホルダーに M2×6 ×1 で固定。
3. L-6 を入れて左右 M2×6 ×2 ずつで固定、ホーンを 1 個付けて M3×6 で固定。
4. トリガー(follower trigger)を M3×6 ×4 で固定。

### ネジが入らないとき(関節 1 の肩パーツ固定 0:30 付近など)

対象はホーンの外周 4 穴に入れる M3×6(上 4 本・下 4 本)。原因は次の順で疑う。

1. ネジの取り違え: M2×6(細い)と M3×6(太い)を混ぜていないか。ホーン外周は M3。
2. 穴の位置ずれ: ホーンは軸のスプラインにどの角度でも刺さるので、印刷パーツの 4 穴と一致しない。
   上ホーンは中央ネジを緩めて少し持ち上げ、角度を合わせて刺し直す。下ホーンは空転する円盤なので指で回して合わせる。
3. ホーンが浮いている / 中央ネジの頭が出ている: 先にホーンを奥まで押し込み、上ホーンの中央 M3×6 を締めてからパーツを載せる。
4. 印刷パーツの穴が細い・サポート材が残っている: 小型ドライバーでサポートを除去、3.0〜3.2mm ドリルか丸ヤスリで貫通穴を広げる。
   ネジ側で強引にタップを切ると印刷パーツが割れる(レジン製は特に)。
   **広げてよいのは M3×6 が「通り抜けて」ホーンに締まる穴だけ。** M2×6 の穴(モーターの耳を留める穴)は
   ネジが樹脂に食い込んで固定する設計なので広げない。
   先に全パーツの M3 貫通穴(肩・上腕・前腕・手首・グリッパ・リーダーホルダー・トリガー)をまとめて広げておくと以後が楽。


### 配線(組み立て後)

- モーターの 3 ピン端子は 1 個に 2 口あり、電気的に並列。片方を前のモーターから、もう片方を次のモーターへ、の数珠つなぎ。
  `基板 → 1(肩回転) → 2(肩上下) → 3(肘) → 4(手首上下) → 5(手首回転) → 6(グリッパ)`
- 基板側の 3 ピンサーボ端子も全部並列なので、どの口に挿しても同じ。
- コネクタは向きが決まっていて逆には刺さらない。無理に押さない。
- 長いケーブルは基板 → 1 と 1 → 2、短いケーブルは手首まわりに使う。印刷パーツの溝や穴にケーブルを通し、関節を動かしても引っ張られない余裕を残す。
- 基板はベースの取付部にはめる。電源はそのアームのモーター電圧に合わせる(リーダーは 7.4V 系のみ)。

### 組み立て後の確認

```bash
scripts/00b_scan_bus.sh both
```

各基板で `id [1, 2, 3, 4, 5, 6]` が出れば配線 OK。欠けている番号があれば、その前後の 3 ピンケーブルを疑う。

## 4. キャリブレーション

```bash
scripts/03_calibrate.sh follower
scripts/03_calibrate.sh leader        # または scripts/03_calibrate.sh both
```

1. 全関節を可動域の**中央**にして Enter。
2. 各関節を**端から端まで**ゆっくり動かして Enter(wrist_roll は 1 回転扱いで動かさなくてよい)。
   キャリブレーションファイルは `id` 名で保存されるので、以降のコマンドで同じ `FOLLOWER_ID` / `LEADER_ID` を使う。
   保存先: `~/.cache/huggingface/lerobot/calibration/{teleoperators/so_leader,robots/so_follower}/<id>.json`

チャット越し(Enter 待ちなし)で進める場合は 2 段階版を使う:

```bash
scripts/03b_calibrate_chat.sh leader mid     # 全関節を中央にした状態で実行
scripts/03b_calibrate_chat.sh leader range   # 実行後に各関節を端から端まで動かす。止めて 8 秒で自動保存
scripts/03b_calibrate_chat.sh leader show    # 保存内容の確認
```

### 手首回転が突然 1 回転する(2026-09-23 に遭遇)

**症状**: テレオペ中、手首回転(wrist_roll, ID 5)だけが突然大きく回る。

**原因**: この関節は 1 回転する扱いなので可動域を 0〜4095 の全周にしている。エンコーダは 4095 の次が 0 に戻るため、
その切れ目をまたぐと読み取り値が 4096 飛び、lerobot が「360 度動いた」と解釈してフォロワーに 1 回転を指令する。
**常用する手首の向きが切れ目の近くにあると多発する。**

**確認**: `scripts/03h_watch_wrist_roll.sh leader 40` を実行して手首を回し、生値が飛ぶか、切れ目までの余裕を見る。

**対策**: 実際にタスクで使う向きで 0 点を取り直す。切れ目が反対側の 180 度先へ移り、通常操作では届かなくなる。

```bash
# 両アームの手首を「実際に使う向き」に揃えてから
scripts/03i_sync_wrist_roll.sh
scripts/03g_calib_backup.sh backup
```

> [!IMPORTANT]
> **必ず `03i`(両アーム同時)を使う。** `03c` で片方ずつ登録すると、その間にもう片方の手首が動いてずれる。
> 2026-09-26 に実際に 78 度ずれた。`03i` は両方に同時に中央合わせを送るので隙がない。

**この関節は録画前に毎回確認すること。** 1 回転する関節なのでトルクが切れている間に手で動かされると基準がずれる。
アームを手で動かしたあと、配線を触ったあとは特に注意。

**運用対処:** リーダーの手首の回転部と固定部にまたがるようマスキングテープを貼り、中央位置で線を引いておく
(2026-09-26 実施)。操作中に線がずれていれば回しすぎなので、切れ目に近づく前に戻せる。
実際、印がない状態では中央から +145 度まで回っていて、切れ目まで 35 度しかなかった。

**ソフト側の対策(導入済み):** `--robot.use_degrees=false` / `--teleop.use_degrees=false` で
関節値を可動域で頭打ちにする方式にした。角度方式では切れ目で 360 度飛ぶが、この方式なら可動域の端で止まる。
`04_teleop.sh` / `06_record.sh` / `08_rollout.sh` の 3 つに入れてある(学習時と推論時で表現を揃える必要があるため)。

> [!NOTE]
> モーターの `Min/Max_Position_Limit` では読み取り値は頭打ちにならない(実測確認済み)。
> 可動域の制限では解決しないので、0 点の位置で対処する。

### 追従が遅い・特定の関節が動かない(2026-09-27)

**症状**: 肘が「全然上がらない」。カメラを動かしているときだけ起きるように見えた。

**原因は移動制限 `max_relative_target`。** これは「1 ステップで現在位置から何単位まで目標を進めてよいか」の設定で、
安全のため 15 にしていた。ところが**サーボは目標との差が小さいとゆっくり動く**ため、常に 15 単位先しか指令されないと
最高速度が出ない。動かす量が大きい肘で最も影響が出て、平均 47 度も遅れていた。

カメラは無実だった。ログ解析でループは 60Hz を完全に維持(10043 回中、50Hz を下回ったのは 4 回)、
通信エラー 0、±100 への張り付き 0%。カメラなしで問題が出なかったのは、単にゆっくり動かしていて制限に当たらなかったため。

**対策**: `04_teleop.sh` の既定を無制限にした。`06_record.sh` はもともと無制限なので条件が揃う。
慎重に動かしたいときだけ `TELEOP_MAX_REL=20` のように指定する。

> [!TIP]
> **テレオペと録画で設定を揃えること。** 片方だけ制限があると、テレオペで確認した挙動が録画時と変わる。

### 可動域が狭いと関節が途中で止まる(2026-09-27)

`use_degrees=false`(頭打ち方式)では、登録した可動域の外に出た値は端で止まる。
最初のキャリブレーションで端まで取り切れていないと、実際に使う範囲で頭打ちになりフォロワーが動かなくなる。

対策は可動域の取り直し。**各関節を機械的に止まるところまで確実に押し当てる。**

```bash
scripts/03j_rerecord_ranges.sh leader     # wrist_roll は変更しない
scripts/03j_rerecord_ranges.sh follower
scripts/03k_widen_joint.sh follower elbow_flex   # 1 関節だけやり直す場合
scripts/03g_calib_backup.sh backup
```

> [!WARNING]
> `03j` は**動かした関節しか記録しない**。動かし忘れた関節は可動域が潰れる。
> 2026-09-27 にグリッパを動かし忘れて幅 7 になり、手で元の値に戻した。5 関節すべて動かすこと。

### 電源(重要・2026-09-26 に判明)

**キット付属の 12V 2A ではフォロワーの電流が足りない。** 6 モーターが同時に動くと電圧が 11.8V → 10.4V まで落ち、
基板がリセットされてテレオペが数秒〜数分で停止する。SO-ARM100 公式の部品表も 12V モーターには **5A 以上**を指定している。

- 対策: 12V 5A のアダプタに交換(SUCCUL B00LG9KUAE ¥2,980)。**2026-09-27 に交換して解決を確認。**

| | 2A(キット付属) | 5A(交換後) |
| --- | --- | --- |
| 定常電圧 | 11.8V | 12.0〜12.1V |
| 負荷時の最低電圧 | 10.4V | 11.1V |
| テレオペ継続時間 | 0.6 秒〜45 秒で停止 | 3 分以上エラーなし |
| 移動制限に当たる割合 | 99.7% | 1.1% |

移動制限に当たる割合が激減した = フォロワーがほぼ遅れずに追従できるようになった。
- 暫定回避: `TELEOP_MAX_REL=4` まで下げると電流のピークが下がり 90 秒以上もつ。
  ただし移動制限に 99.7% 当たり、フォロワーが常に遅れる。**この状態で録画すると遅延がデータに入るので本番には使わない。**

切り分け方: 静止時は ping も sync_read も 100% 成功するのに、モーターが動くと落ちる → 電源を疑う。
`Present_Voltage` を動作中に監視して 10.5V を割るなら電流不足。

### キャリブレーションの保護(重要)

保存先の `~/.cache/huggingface/lerobot/` は**消えやすい**。2026-09-23 に実際に中身が空になり、
テレオペ起動時に「Mismatch between calibration values ... or no calibration file found」と出て
新規キャリブレーションが始まりかけた。**ここで Enter を押すと調整がすべて失われる。Ctrl+C で中止すること。**

```bash
scripts/03g_calib_backup.sh verify    # モーターの EEPROM とファイルが一致しているか確認
scripts/03g_calib_backup.sh backup    # キャッシュ → calib/(git 管理)へ控えを取る
scripts/03g_calib_backup.sh restore   # calib/ → キャッシュへ戻し、モーターにも書き込む
scripts/03f_recover_calibration.sh    # ファイルを消した場合、モーターの EEPROM から作り直す
```

控えは `calib/` に置いてあり git に入っている。**調整を変えたら毎回 `backup` すること。**

> [!WARNING]
> **EEPROM への書き込みはトルクを切ってから行う。** トルクが入ったまま書くと、読み戻しは成功するのに
> 電源を入れ直すと元に戻る。2026-09-07 に入れた肩上下の -15.2 度補正がこれで失われ、09-23 に入れ直した。
> `03c` / `03d` / `03g restore` は内部で `disable_torque()` してから書くよう修正済み。

## 6. カメラ

```bash
scripts/05_find_cameras.sh
```

初回は macOS がカメラ許可を求めるので、**必ず自分のターミナル(Terminal.app / iTerm)から実行**して許可する。
Claude のプロセスからはカメラ権限(TCC)が下りないため、この 1 コマンドだけは手動実行が必要。
結果の画像は `outputs/captured_images/` に保存されるので、Claude 側から確認できる。

### 手持ちカメラ

| 用途 | 機種 | 備考 |
| --- | --- | --- |
| 手首 or 俯瞰 | InnoMaker 1080P USB2.0 UVC(2026-09-10 購入) | 基板は 38×38mm が標準サイズ。公式マウントは 32×32mm 用なので要確認 |

InnoMaker の基板が 38×38mm の場合、SO-ARM100 公式の `Wrist_Cam_Mount_32x32_UVC_Module` はそのままでは合わない。選択肢:

1. 俯瞰カメラとして使う(マウント不要。クランプアームや三脚に固定)
2. 38×38mm 対応の手首マウントを探す(Printables/Thingiverse に有志のモデルあり)
3. 公式 32×32 マウントを 38×38 用に改造して印刷
出てきた index を `config.env` の `CAMERAS` に反映。複数台なら `{ front: {...}, wrist: {...} }` と列挙。
iPhone を使う場合は連係カメラ(Continuity Camera)で OpenCV から見える。

### 手持ちカメラ

- 2026-09-10: InnoMaker 1080P USB2.0 UVC カメラを購入。
  **基板サイズは 38×38mm の製品が多い**が、SO-ARM100 公式の手首マウントは **32×32mm UVC モジュール用**なので
  そのままでは付かない可能性が高い。届いたら基板の実寸(ネジ穴の間隔も)を測ってから、
  38×38mm 用マウント(Waveshare OV9281 用など)を探すか、俯瞰カメラとして使う。
- macOS のカメラ権限の都合で、検出は**必ず自分のターミナルから**実行する(Claude のプロセスからは TCC で拒否される)。

### カメラの取り付け

#### 俯瞰カメラ(C270nd + エレコム PWCZARMTBK)

**C270nd に 1/4 インチの三脚ネジ穴はない。** 公式の取り付け穴は存在せず、付属のクリップだけ。
アーム(対応天板厚 65mm、耐荷重 2kg)は台に固定できるので、問題は「カメラをアームに留める方法」だけ。

1. **アーム付属のスマホホルダーで挟む(まず試す。追加費用ゼロ)**
   C270 の外形は 72.91 × 66.64 × 31.91mm。ホルダーは幅 85mm まで対応なので、広い面(約 73mm)を挟めば入る。
   前面が丸いので回りやすい。滑り止めゴムかテープを噛ませると安定する。
2. **C270 のクリップを台の縁や棚に直接挟む(アーム不要)**
   クリップはもともとモニタの縁に留める設計。高さが出る場所があればこれが一番確実。
3. **3D プリントのアダプタ**
   「Logitech C270 Tripod Mount」で無料 STL が多数。分解不要タイプ(`Logitech C270 Screw Mount (no disassembly)`)もある。
   印刷したらアームの 1/4 ネジに直付けできる。

位置は「画面だけ見て自分がそのタスクをこなせるか」で決める。決めたら二度と動かさない。

#### USB 配線(2026-09-26 確定)

```
Mac ポート0 ── フォロワー基板 (USB S/N XXXXXXXXXX)  直挿し
Mac ポート1 ── リーダー基板   (USB S/N YYYYYYYYYY)  直挿し
Mac ポート2 ── Anker Type-C ハブ ┬── InnoMaker(手首)
                                  └── C270nd(俯瞰)
```

> [!WARNING]
> **Anker ハブにモーター基板を 2 枚挿すと片方しか認識されない。** 同種の USB シリアル機器を並べたときの相性問題で、
> ポートを変えても解決しない。**基板 2 枚は Mac 本体に直挿しすること。**
> 2026-09-26 に丸 1 時間これで詰まった。症状は「フォロワーだけ `/dev/tty.usbmodem*` に出てこない」。
> 切り分けは「片方だけ挿して見えるか」。1 枚なら見えるのに 2 枚だと消えるならこの問題。

基板のポート名は USB シリアル番号から決まるので、**挿す場所を変えても名前は変わらない**(`config.env` の修正不要)。
カメラの index は挿し替えで変わるので、`scripts/05b_test_cameras.sh` で確認すること。

#### USB 帯域の落とし穴(2026-09-23 に遭遇)

カメラ 2 台を 1 つのハブに載せると、**既定の 1920×1080 無圧縮では 1 台しか開けない**。
1080p の無圧縮 30fps は約 995 Mbps で、USB 2.0 の 480 Mbps を 1 台で超えるため。

`640×480` + `fourcc: MJPG` にすれば 3 台同時に開ける(実測確認済み)。学習に使う解像度も 640×480 なので実害はない。
確認は `scripts/05b_test_cameras.sh`(個別に開く → 全部同時に開く、まで試す)。**ターミナル.app から実行すること。**

確定した割り当て:

| index | カメラ | config.env での名前 |
| --- | --- | --- |
| 0 | InnoMaker U20CAM-1080P(手首) | `wrist` |
| 1 | Logicool C270nd(俯瞰) | `top` |
| 2 | 内蔵 FaceTime | 未使用 |

#### 手首カメラ(InnoMaker U20CAM-1080P、32×32mm)

公式マウント `SO101_Wrist_Cam_Hex-Nut_Mount_32x32_UVC_Module` を使う。**3D プリントが必要。**

必要な部品:

| 部品 | 数 | 備考 |
| --- | --- | --- |
| Hex-Nut Recess Camera Adapter(3D プリント) | 1 | ツリーサポート、インフィル 40% 推奨 |
| M2 ネジ | 4 | カメラ基板 → アダプタ |
| M3×8mm ネジ | 2 | アダプタ → 手首 |
| M3 六角ナット | 2 | 手首のくぼみに埋める |

**M3×8 と M3 六角ナットはキットに入っていない**ので買い足す(M2〜M5 のネジ・ナット詰め合わせで可)。

手順:

1. アダプタを 3D プリントする(プリンタがなければ DMM.make 等の出力サービス)。
2. **モーター 6(グリッパ)を外す。** 可動爪は付けたままでよい。
3. Wrist Roll Follower のくぼみに M3 六角ナットを 2 個入れる。
4. モーター 6 を元の M2 ネジで戻す。
5. アダプタを M3×8 ネジ 2 本で固定する。
6. カメラ基板の 4 穴をアダプタに合わせ、M2 ネジ 4 本で留める。
7. 解像度 640×480 / 30fps に設定し、**レンズを回してピントを合わせる**(M12 レンズなので手で回る)。

> [!TIP]
> 3D プリントが用意できるまでは**俯瞰カメラ 1 台だけで始めてよい**。公式チュートリアルの基本例もカメラ 1 台。
> Phase 1〜2(ACT で自律動作)は 1 台で成立する。手首カメラは後から足せばよいが、
> **足したらデータを録り直す**(観測の構成が変わるため)。それが嫌なら最初から 2 台そろえてから録画を始める。

## 7. データ収集(ローカル保存のみ)

Hugging Face は使わない。`hf auth login` は不要で、データは `data/<名前>/` に保存される(git 管理外)。
**カメラ権限の都合で「ターミナル.app」から実行すること。**

```bash
scripts/06_record.sh so101_cube 50 "Pick up the red cube and put it in the box"
```

- 録画中のキー: `n` または → 次へ、`r` または ← 撮り直し、`q` または ESC 終了。
- 1 エピソード 30 秒、リセット 10 秒が既定。変えるなら `EPISODE_SEC=20 RESET_SEC=8 scripts/06_record.sh ...`。
- カメラなしで動作確認だけしたいときは `NO_CAM=1`。**本番では使わない。**
- 中身の確認: `scripts/06b_dataset_info.sh so101_cube`(エピソード数、タスク、特徴量を表示)

### 録画が 30Hz に届かないとき(2026-09-27 に遭遇)

`Record loop is running slower (18.6 Hz) than the target FPS (30 Hz)` と出たら、フレームが落ちてデータが劣化する。
**本番前に必ず 2 エピソードで速度を確認すること。**

```bash
rm -rf data/speedtest && NO_DISPLAY=1 scripts/06_record.sh speedtest 2 "speed test"
```

効いた対策(既定に組み込み済み):

| 対策 | 内容 |
| --- | --- |
| コーデック | `libsvtav1`(CPU)→ `h264_videotoolbox`(Apple Silicon のハードウェア) |
| エンコードスレッド | 2 → 4 |
| 映像表示 | `NO_DISPLAY=1` で rerun を切る |

環境変数で切り替えられる: `VCODEC=h264` `ENC_THREADS=8` `NO_DISPLAY=1`。

> [!NOTE]
> lerobot が受け付けるコーデックは `auto, h264, h264_videotoolbox, h264_nvenc, h264_qsv, h264_vaapi,
> hevc, hevc_videotoolbox, hevc_nvenc, libaom-av1, libsvtav1` のみ。`libx264` は指定できない。

> [!NOTE]
> `failed to set fourcc=MJPG` の警告はこの環境では常に出る(カメラが非圧縮で動く)。
> 640×360 なら帯域は足りているので実害はない。解像度を上げると問題になる。

### 録り方のコツ

- 毎回**同じ手順・同じ速さ**で動かす。一貫性が回数より効く。
- 対象の置き場所は最初は 5 か所程度に限定する。SO-101 の到達範囲は 40cm 台なので台の上に収める。
- 途中でためらって止まらない。失敗したら `r` で撮り直す。
- **照明を一定に保つ。** 手首カメラに窓が入っているので、録画の時間帯は固定する。

### 追加で録る(タスクを増やす / エピソードを足す)

同じデータセットに `--resume=true` で足す。`--dataset.single_task` を変えれば別タスクとして記録される。

```bash
scripts/06_record.sh so101_cube 50 "Pick up the blue cube and put it in the box" --resume=true
```

`--resume=true` のときエピソード数は**追加する数**。
