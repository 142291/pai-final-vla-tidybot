# データ v3 の段取り(2026-10-18〜20)

> 2026-10-17 の切り分けで、遅延・カメラ位置・キャリブレーションを潰しても π0.5 が
> 「近くまで行って僅かにずれる」ことが残った。原因はデータ(77 本、照明の幅が狭い、
> 掴む直前の実演が少ない)と判断。最終課題の本命データとして撮り直す。
> 録り方の基本は `recording-protocol.md` に従う。ここは v3 で追加・変更する点だけ。

## 方針

| 項目 | v2 | v3 |
| --- | --- | --- |
| タスク | 赤 → 箱 の 1 種類 | **赤・黄・紫 → 箱 の 3 種類**(言語で区別できるように) |
| 本数 | 77 本(50 本を 19 分で) | **各色 50 本 = 150 本**、3 セッションに分ける |
| 照明 | ほぼ 1 条件(輝度 std 1.9) | **朝・昼・夜の 3 条件**。各セッションで 3 色を同数ずつ(色と照明を交絡させない) |
| 位置 | 9 区画ローテーション | 同じ。各色・各セッションで 9 区画を一巡 |
| 掴む直前 | 開始はすべてホーム姿勢 | 1 セッションあたり各色 2〜3 本は**キューブの数 cm 手前・少し外れた位置から開始して補正して掴む**実演を混ぜる(全体の 1〜2 割) |

最後の行が今回の症状(僅かにずれたまま掴みにいく)への直接の対策。ずれた位置からの
立て直しを見せないと、ポリシーはずれを直す動きを知らない。

## 段取り

カメラは 10-17 に v2 の画角へ合わせ直した(dx=+3.8, dy=-3.0px)。**v2 の 77 本と混ぜて使える**ように、
各セッションの前に必ず `ONESHOT=1 scripts/05f_align_camera.sh` で |dx|,|dy| ≤ 4px を確認する。

**リーダーアームを接続すること**(10-17 時点で未接続。`/dev/tty.usbmodemYYYYYYYY`)。

### 各セッション(約 30〜40 分)

```bash
cd ~/project/ai-arm
ONESHOT=1 scripts/05f_align_camera.sh          # カメラ位置の確認
scripts/05e_check_lighting.sh so101_cube_v2    # いまの照明を記録(外れていてよい。むしろ v2 と違う照明が価値になる)

# 1 回目のセッションだけ --resume を付けない。2 回目以降は --resume=true
RESET_SEC=20 NO_DISPLAY=1 scripts/06_record.sh so101_cube_v3 17 "Pick up the red cube and put it in the box"
RESET_SEC=20 NO_DISPLAY=1 scripts/06_record.sh so101_cube_v3 17 "Pick up the yellow cube and put it in the box" --resume=true
RESET_SEC=20 NO_DISPLAY=1 scripts/06_record.sh so101_cube_v3 16 "Pick up the purple cube and put it in the box" --resume=true
```

タスク文は**一字一句この 3 つ**に固定する(推論時も同じ文字列を使う)。

| セッション | 時間帯 | 照明 |
| --- | --- | --- |
| S1 | 10/18 朝(〜10 時) | 外光あり・室内灯なし |
| S2 | 10/18 昼〜夕方 | 外光＋室内灯 |
| S3 | 10/18〜19 夜 | 室内灯のみ(＋デスクライト) |

### 撮り終わったら

```bash
scripts/06c_check_dataset.sh so101_cube_v3     # 位置の散らばり、照明 std ≥ 8 を確認
```

その後 H200 へ転送して π0.5 を学習(`h200-training.md` の π0.5 の手順。データセットを
v2＋v3 にするかは、v3 単独と両方を学習して評価で選ぶ)。長時間ジョブの前に必ず `07b` で起動確認。

## 評価(ラウンド 1)

固定 10 配置 × 色ごと 10 試行。順序は事前に乱数で決める。成功率は Wilson の 95% 信頼区間つきで記録。
v2 の π0.5(step 14000)も同じ条件で測っておく(ラウンド 0 = 比較の基準)。

## 進捗(2026-10-18)

### S1(朝)を収録 → 監査 → 途中経過の学習

| | 赤 | 黄 | 紫 |
| --- | --- | --- | --- |
| 収録 | 17 | 17 | 16 |
| 開始位置の散らばり(幅×高さ) | 64%×77% | **45%×44%(中央寄り)** | 75%×68% |

照明は 1 セッション内なので均一(輝度 std 3.8、✗)。S2・S3 で広げる。黄色は S2 以降で端を多めに。

### 監査(`scripts/06d_audit_dataset.py`)

全フレームを復号して、ラベル(指示した色が箱に入ったか)・巻き添え・開始・画角・映像の固まり・数値・遅れ・静止を
1 本ずつ確認する。自動判定の ✗ は**必ず開始/終了フレームを目で見て**確定する
(明るい光で赤が橙に見える、アームが箱を隠す、などの誤検出がある)。

| データ | 結果 |
| --- | --- |
| v3 S1(50 本) | 除外 3 本: ep17(一度も掴んでいない)、ep1(終了時 6.6 秒静止)、ep18(開始時 5.7 秒静止)。他の ✗ は誤検出 |
| v2_clean(41 本) | **v3 と画角が違う**(箱の中央値 y0/y1 = 197/299 vs v3 186/285、11〜14px)。さらに置き終わる前に切れた回(ep1)、縁に置いた回(ep6, 7, 37, 38)、**アームが箱を動かした回(ep31)** |

→ 途中経過の学習は **v3 S1 の 47 本のみ**(`data/so101_cube_v3_s1`、赤 16・紫 16・黄 15)。v2 は混ぜない。
編集後のデータは、47 本すべてで action が元と完全一致・映像フレーム数一致・先頭/末尾フレームの画素差 ≤3.3(再符号化の誤差)を確認済み。

### 学習(H200、tmux `pi05_v3s1`、`~/ai-arm/run_pi05_v3s1.sh`)

- 他プロジェクトの vLLM(docker `vllm-chokotei`、Qwen3.6-35B-A3B、約 108GB)を**停止**して実施。終わったら `docker start vllm-chokotei` で戻す。
- 前回の π0.5 は gradient checkpointing ありで **4.8 s/step**(batch 32)。切ると batch 32 は OOM(127GB)。
  **batch 16・checkpointing なしで 1.68 s/step**(1 サンプルあたり 1.4 倍速)、16,000 step(サンプル数は前回の 8,000×32 相当)、2,000 step ごとに保存。
- 学習中(GPU 121GB 使用)は推論サーバーで新しいモデルを読むと OOM の恐れがあるので、評価は学習後に行う。

### S2(昼)・S3(夜)を収録 → 監査(2026-10-18〜19)

| セッション | 照明 | 収録 | 除外 | 使用 |
| --- | --- | --- | --- | --- |
| S1 | 朝の外光(輝度 116) | 50 | ep1, 17, 18 | 47 |
| S2 | 赤の前半は**強い直射**(輝度 167、+15σ、日差しの縞)→ 雲で暗め → 黄・紫はカーテン越しの昼光(輝度 114、暖色) | 50 | ep50(開始/終了とも約 3 秒静止) | 49 |
| S3 | 夜の室内灯＋デスクライト(輝度 96、暖色) | 50 | ep100(開始 2.4 秒静止)、ep144(終了 2.1 秒静止) | 48 |

- 監査は追記分だけ `AUDIT_EPS=50-66` のように絞って回し、✗ は `scripts/06e_startend_sheet.py` の開始/終了一覧で全件目視した。
  **150 本すべてで、指示した色のキューブが最後に箱の中にあることを確認**(ラベル違い・巻き添えは 0)。
  自動判定の ✗ の大半は誤検出: 直射で赤が橙・桃に、黄がほぼ白に見える / 夜は箱の中が一番明るい領域にならず箱を見失う / 縁に置くと箱の外と判定される。
- フレーム落ちの目安(1 フレームでの関節の飛び)は全セッションで最大 10.4(基準 12)。録画速度の警告はリセット中か撮り直した回のみ。
- 直射では黄色がほぼ白に見えるため、黄・紫はカーテン越しで撮った(色の区別が課題の核心なので)。直射の見本は赤で約 10 本確保。
- 手首カメラが S3 の前に「開けるが読めない」状態になり、USB の挿し直しで復帰(番号の入れ替わりなしを確認)。
- リセット時間は S3 の黄・紫から 10 秒に短縮(静止の問題は出なかった)。
