# 録画プロトコル

> 2026-09-28、最初の 24 エピソード(`data/so101_cube/`)を検証して作った。
> あの 24 本は**ばらつきが逆**だった。同じ失敗を繰り返さないための手順書。

## なぜ必要だったか

最初の 24 本を開始フレームから自動解析した結果:

| | 実測 | あるべき姿 |
| --- | --- | --- |
| 赤キューブの位置 | 640×360 の画面中 **40×28 px に固定**(ep1 除く 23 本) | 作業範囲全体に散らす |
| アームの開始姿勢 | 畳んだ状態〜伸ばした状態までバラバラ | 毎回同じ |

汎化は**対象物の位置のばらつき**から来る。アーム初期姿勢のばらつきからは来ない。
逆になっていると、ポリシーは「毎回違う姿勢から固定の 1 点へ行く」という
余計に難しい問題を、1 姿勢あたり数本のデータで解かされることになる。

初回の自律実行で「キューブの方へは向かったが掴めなかった」のはこれで説明がつく。
方向は覚えられても、開始姿勢が学習時と違えば覚えた軌道が当たらない。

`ep1` は開始時点で赤キューブが箱の中にあった(リセット漏れ)。`ep0-3` は
27-30 秒の上限に張り付いていて、待ち時間や失敗のやり直しを含んでいる可能性が高い。

## 照明もばらつかせる

> 2026-09-29 に実際に起きた失敗。50 本を 19 分で撮ったので照明が完全に均一
> (輝度 std 1.9)になり、翌朝 8 時には最大 **12.8σ の分布外**となって
> ACT も SmolVLA も掴めなくなった。両方が同じ方向に外すのが症状だった。
> 赤の検出面積が 800 → 398 と半減しており、色の見え方自体が変わっていた。

キューブ位置と同じ話で、**ばらつきが必要なところにばらつきが無い**と汎化しない。
1 セッションで一気に撮ると必ずこれを踏む。

- **時間帯を分ける。** 朝・昼・夜で 1/3 ずつが理想
- **カーテンの開閉を変える。** 外光の入り方が変わる
- **室内灯の数を変える。** 明るさだけでなく色温度も変わる

撮り足すときも、いま現在の照明条件が既存データと違うなら、それ自体が価値になる。

## 撮る前に 1 回だけやること

テレオペで**掴める範囲の四隅**を確認する。ここで確認した範囲が、
そのままポリシーが汎化できる範囲の上限になる。

```bash
scripts/04_teleop.sh
```

同時に**ホーム姿勢を 1 つ決める**。毎エピソードの開始をこの姿勢に揃える。
畳んだコンパクトな姿勢がおすすめ(カメラに写る面積が小さく、再現しやすい)。

## 各エピソード

1. **開始** — アームはホーム姿勢。3 つのキューブは配置済み。
2. **掴んで箱に入れる。**
3. **入った瞬間に `n`(または →)を押す。**
   `EPISODE_SEC=30` は上限であって目標ではない。10 秒で成功したなら 10 秒で切る。
   成功後に放置した分は「何もしない」が正解動作として学習される。
4. **失敗したら `r`(または ←)。** そのエピソードのバッファが破棄されて撮り直しになる。
   掴み損ねた回を無理に成功扱いしない。

## 各リセット("Reset the environment" と鳴っている間)

この区間は `record_loop` に `dataset` が渡らないので 1 フレームも保存されない。
一方 `teleop` は渡ったままなので、**リーダーでフォロワーを動かせる**。

1. **赤キューブを前回と違う位置に置く。** ここが汎化の源。
   端・手前・奥も必ず使う。真ん中ばかりにしない。
2. **黄・紫のダミーも動かす。** 動かさないと「赤」ではなく「その場所にある物」を
   学んでしまう。Phase 4 の言語条件付けで効いてくる。
3. **アームをホーム姿勢に戻す。**
4. 終わったら `n` で早めに切り上げてよい(待つ必要はない)。

> [!TIP]
> 位置をランダムに置くと中央に偏りやすい。作業範囲を 3×3 の 9 区画と考えて
> 順番に回すと、50 本で 1 区画あたり 5-6 本になり偏らない。

## コマンド

```bash
RESET_SEC=20 scripts/06_record.sh so101_cube_v2 50 "Pick up the red cube and put it in the box"
```

途中で中断したら `--resume=true` を付けて追加する(エピソード数は**追加する数**):

```bash
RESET_SEC=20 scripts/06_record.sh so101_cube_v2 20 "Pick up the red cube and put it in the box" --resume=true
```

> [!NOTE]
> タスク説明の文字列は途中で変えないこと。ACT は言語を使わないので影響しないが、
> Phase 4 の SmolVLA では意味を持つ。`data/so101_cube/` はこれを揺らしてしまい、
> 同じ作業に "place it in the bowl" と "put it in the box" の 2 つが付いている。

## 撮り終わったら検証する

```bash
scripts/06c_check_dataset.sh so101_cube_v2
```

赤キューブ位置の分布が十分に散っているかを数値で出す。
x/y の範囲が画面の 30% 未満しかなければ、撮り方を見直すこと。
照明のばらつき(輝度 std)が 4 未満なら、別の時間帯・別の照明で撮り足すこと。

実行の直前に、いまの照明が学習データの分布内かを確認できる:

```bash
scripts/05e_check_lighting.sh so101_cube_v2
```

俯瞰カメラで 3σ 以内なら分布内。6σ を超えていると、掴めなくても
ポリシーのせいではない。
